## 1. What we are building

A fast, bilingual (ar/en) hotel website for two properties, with a real booking-request flow, built as a foundation that later takes online payment (Tap Payments) and instant booking.

Replaces the current site built on Hostinger Horizons (JS-rendered, canonical pointing to home, template placeholders, broken forms). Do not copy its structure or its problems.

**Properties**
- `airport-road` — أرمادا ريزيدنس – طريق المطار / Armada Residence – Airport Road (hotel apartments, ~108 units)
- `shafa-road` — أرمادا ريزيدنس – طريق الشفا / Armada Residence – Shafa Road (hotel, ~32 rooms)

**Phases**
1. Frontend MVP: all pages, bilingual, SEO complete, booking-request form that emails the hotel + confirms to guest.
2. Backend: Supabase schema, admin, archive of real bookings, Excel export.
3. Payment: Tap Payments link generated on "confirm", webhook updates status.
4. Launch: DNS switch, 301s from old URLs, Search Console, tracking live.

Never pull phase 3 work into phase 1. Ship phase 1 even if Tap is not live.

## 3b. Motion system (polish sprint, 11 Oct 2026)

Tokens live in `src/styles/motion.css` and are the only durations, easings and distances the site's own motion may use (legacy sections keep theirs). Under `prefers-reduced-motion` every token is 0 and every element renders its final state at once; JS-driven motion (reveal, counters, glow, nav ink, drawer) checks `reducedMotion()` from `src/lib/client.ts` as well.

| token | value | use |
|---|---|---|
| `--motion-fast` | 200 ms | hover, focus, icon morph, small state changes |
| `--motion-base` | 400 ms | reveal, drawer, cross-fade, nav ink |
| `--motion-slow` | 700 ms | rules being drawn, hero rule, long settles |
| `--motion-count` | 1200 ms | count-up figures |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | arriving |
| `--ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | moving / morphing |
| `--ease-in` | `cubic-bezier(0.55, 0, 1, 0.45)` | leaving |
| `--motion-shift-sm` | 16 px | text, labels, small elements |
| `--motion-shift-lg` | 24 px | cards, sections, media |
| `--motion-stagger` | 60 ms | between siblings |
| `--motion-stagger-fast` | 50 ms | between hero words |
| `--motion-hero-hold` | 6000 ms | the home hero slideshow: how long each photo stays (6 Nov 2026) |
| `--motion-hero-fade` | 1200 ms | the home hero slideshow: the cross-fade between photos |
| `--motion-marquee` | 40000 ms | the home partners strip «شركاؤنا»: one full loop of the logos (7 Nov 2026) |
| `--motion-reviews-hold` | 6000 ms | the home reviews carousel: how long each position stays before it advances (7 Nov 2026) |

Rules: transform and opacity only (no width/height/margin/font-weight animation), `will-change` only on the hero pattern layer and the glow, IntersectionObserver instead of scroll listeners, CLS 0, direction follows the writing direction (`[dir='rtl']` overrides, logical properties, the `translate` property for arrows so the RTL `rotate` is untouched), light and dark alike. Component scripts are ES modules that run once per full load, so each registers an idempotent `init` through `onPageLoad` (`astro:page-load`) and marks bound elements with a data attribute; timers/observers are cleared on `astro:before-swap`. View transitions: `ClientRouter` on every site page except `/discover-taif/`, `/partners/*` and `/menu/`. The internal review page `/_motion/` was removed on 22 Oct 2026; review motion on the real pages. Partners button (2 Nov 2026, «raised and refined» — replaces the hairline pill of 23 Oct): in the utility row, 24 px high; a bronze gradient Bronze `#A97C50` (top edge) → Bronze Deep `#976E47` at 20 % → Bronze Text `#8A6239`, so the white text and arrow sit on Bronze Deep or darker (≥ 4.5:1, measured pixel by pixel by `scripts/partners-button-check.mjs`; no text colour passes over both ends of the plain two-stop gradient); a 1 px light top highlight and a soft navy shadow; hover / focus lifts it 1.5 px over `--motion-fast`, a larger shadow fades in (opacity) and one light sweep crosses it once from the reading-start edge over `--motion-base`; active presses it down; a Bronze Bright focus ring; reduced motion → no lift, no sweep; it stays secondary to «احجز الآن» (the header booking button since 3 Nov 2026). ## 9c. Dashboard interaction rules (Ahmed, 28 Oct 2026 — DECISIONS.md 2026-10-28)

- **Dialogs never close by accident.** Every modal, drawer, sheet and confirm is the shared `Modal` / `Drawer` of `admin/src/components/ui.tsx` with the one dirty guard `admin/src/lib/dirty.ts` — no per-dialog or per-page patches. An outside press (click, tap, pointer-down, a press that starts inside and ends outside such as a text-selection or scrollbar drag) does nothing: no close, no flicker, no focus loss; no swipe-to-dismiss. A dialog closes only through its × or its «إلغاء» («إغلاق» for read-only ones, `CancelButton`), or after a successful save; Esc behaves exactly like ×. Dirty = any control inside differs from its value at open (text after `west()` + trim, numbers as numbers — «٥٠» = «50»; checks / radios / `aria-pressed` chips / segments; a control added or removed after the scope settled; typing then restoring = clean): × / «إلغاء» / Esc open «تعديلات غير محفوظة» — «لديك تعديلات لم تُحفظ في هذه النافذة. هل تريد الإغلاق وتجاهلها؟» — «متابعة التعديل» (default focus; Esc) / «تجاهل التعديلات والإغلاق» (destructive); the confirm itself ignores outside clicks. While a save is in flight × and «إلغاء» are disabled and Esc is ignored (`busy`); a failed save keeps the dialog open, still dirty, with the error. Page-level forms (Settings' cards, the permission matrix) wrap in `<DirtyScope>`: the sidebar, a branch switch and sign-out go through `useLeaveGuard` and ask the same with «في هذه الصفحة»; `beforeunload` is registered only while something is dirty; a successful save re-baselines through `data-dirty-version`. No field saves itself on blur (the booking details' internal notes have an explicit «حفظ الملاحظات» button, 28 Oct 2026): a save is always a button, and it re-baselines its scope. Focus trap, inert background, focus return, RTL and Western digits unchanged.
- **No lost text (5 Nov 2026, DECISIONS.md 2026-11-05).** Auth events for the signed-in user never remount a screen (`lib/session.tsx`); a newer deploy shows «يوجد تحديث جديد للوحة» / «تحديث الآن» and never reloads by itself (`lib/version.ts`, `components/UpdateBar.tsx`, `version.json`); every dialog, drawer and `DirtyScope` keeps its unsaved values in sessionStorage per tab and record and offers «استرجاع المسودة» / «تجاهل» after a reload (`lib/dirty.ts`; `draftKey` for a dialog whose title does not name its record; rich editors through `data-draft-mirror`; never passwords or codes). E2e: `admin/tests/draft-check.mjs`.
- **Printouts (5 Nov 2026, DECISIONS.md 2026-11-05).** A print rule is always scoped to its page (`body:has(…)`), never `body *`. «التقارير» prints with `@page` margin 0 (no browser header / footer, no URL), our own header (logo, «تقرير الأداء», period, comparison, branch) and footer («طُبع في …» · «للاستخدام الداخلي») repeated by a real `<table>` frame, «صفحة N من M» in a Chrome page margin box, each section on a new page, no break inside a KPI / chart / table row. E2e: `admin/tests/print-check.mjs` (PDF pages rendered with pdf.js → `screenshots/print/`).
- **Start-and-end rule (site and dashboard).** Popovers, menus, dropdowns, the date picker, the WhatsApp chooser, the country list and the booking drawer backdrop close on an outside press only when the press starts AND ends outside — `onOutsidePress` in `src/lib/client.ts` is the one implementation (pointer events; `click` is never used for this, since the browser dispatches it to the common ancestor of the down and up targets).
- **A bare «إلغاء» only ever closes a dialog (task 5 D, 28 Oct 2026).** A button whose whole text is «إلغاء» is the dialog's `CancelButton` and nothing else; a button that performs an action names it with a specific verb phrase in the same style («إلغاء الحجز», «إيقاف» for an active rate override with `aria-label` «إيقاف السعر الاستثنائي {dates}» and the undo toast «تم إيقاف السعر الاستثنائي»). `dashboard-check` scans every page it visits.

VAT, notes, the coordination flag, then two signature blocks side by side («توقيع الضيف» / «توقيع موظف الاستقبال», each with name, signature and date lines). `PrintSheet` in `Bookings.tsx`, portalled into `<body>` while the details are open, shown only by the print stylesheet (`styles.css → .print-sheet`); the screen UI is unchanged. ## 12. Working rules

- Decisions live in `DECISIONS.md`; append, don't rewrite history. Check it before proposing an alternative.
- Small commits with clear messages. Never force-push. Never commit secrets, `.env`, or guest data.
- **Waiting on GitHub (Ahmed, 9 Nov 2026).** Before the first push of a session, read https://www.githubstatus.com/api/v2/summary.json: if Actions or Pages is not "operational", finish the local work, commit and hand over without pushing. In any session the total waiting on CI or deploys is capped at 30 minutes; a GitHub-side failure gets at most two retries, 15 minutes apart, then hand over with what is live.
- The fast checks (§11) pass locally before every commit and every push; the heavy checks (browser, pixel guard, sample qa) pass in GitHub Actions before every deploy, which waits for them; and the browser checks pass on the live site after every deploy.
- Do not change the brand tokens, terminology, or site map without asking.
- When data is missing, stop and list exactly what is needed from Ahmed — do not fill gaps with plausible content.
- Flag issues early and plainly; do not pad reports with what went fine.
- Test-only secrets on Supabase preview branches (Ahmed, 3 Nov 2026 — a standing approval, not to be asked again): `BOOKING_TEST_TOKEN` (from .env) and the Resend QA key (.env `RESEND_QA_API_KEY`, set as `RESEND_API_KEY`) may be set on a PREVIEW branch for the dashboard e2e — never on production — with the safeguards: the `secrets:*` deny replaced by narrow denies (production refs, unset, list) plus one allow for `secrets set --project-ref <branch-ref> --env-file`, the values in a temp file never printed and deleted right after, the original deny restored immediately. Any other secret, or any secret on production, still needs Ahmed's explicit OK.
- **Spending (Ahmed, 10 Nov 2026 — DECISIONS.md 2026-11-10 «Standing rules»).** Stop and ask Ahmed before anything that costs money, however small: a Supabase preview branch or any paid add-on, paid API calls, a purchase or a plan change. The question states the expected cost (rate and likely total) and waits for his OK; an earlier OK covers only the action it was given for. Why: in session 23 a test branch was created without asking — the idea was right, the missing OK was not. The standing approval for test-only secrets on a preview branch (above) covers the secrets, never the branch itself.
- **Language of notes (Ahmed, 10 Nov 2026 — DECISIONS.md 2026-11-10 «Standing rules»).** Every progress note, question and hand-off to Ahmed is in Arabic (Egyptian Arabic is fine), with code, file names and commands left as they are. Never a note in any other language (a note in Chinese appeared in session 23). Code, commits and docs stay in English (§ top).
- Deliverables are self-contained and portable (static build folder, PDFs for management, Markdown briefs for external tools).
