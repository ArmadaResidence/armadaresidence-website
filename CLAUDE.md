## 1. What we are building

A fast, bilingual (ar/en) hotel website for two properties, with a real booking-request flow, built as a foundation that later takes online payment (Tap Payments) and instant booking.

Replaces the current site built on Hostinger Horizons (JS-rendered, canonical pointing to home, template placeholders, broken forms). Do not copy its structure or its problems.

**Properties**
- `airport-road` — أرمادا ريزيدنس – طريق المطار / Armada Residence – Airport Road (hotel apartments, ~108 units)
- `shafa-road` — أرمادا ريزيدنس – طريق الشفا / Armada Residence – Shafa Road (hotel, ~32 rooms)

**Phases**
1. Frontend MVP: all pages, bilingual, SEO complete, booking-request form that emails the hotel + confirms to guest.
2. Backend: Supabase schema, admin, archive of real bookings, Excel export.
3. Payment: Tap Payments link generated on "confirm", webhook updates status.
4. Launch: DNS switch, 301s from old URLs, Search Console, tracking live.

Never pull phase 3 work into phase 1. Ship phase 1 even if Tap is not live.

## 3b. Motion system (polish sprint, 11 Oct 2026)

Tokens live in `src/styles/motion.css` and are the only durations, easings and distances the site's own motion may use (legacy sections keep theirs). Under `prefers-reduced-motion` every token is 0 and every element renders its final state at once; JS-driven motion (reveal, counters, glow, nav ink, drawer) checks `reducedMotion()` from `src/lib/client.ts` as well.

| token | value | use |
|---|---|---|
| `--motion-fast` | 200 ms | hover, focus, icon morph, small state changes |
| `--motion-base` | 400 ms | reveal, drawer, cross-fade, nav ink |
| `--motion-slow` | 700 ms | rules being drawn, hero rule, long settles |
| `--motion-count` | 1200 ms | count-up figures |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | arriving |
| `--ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` | moving / morphing |
| `--ease-in` | `cubic-bezier(0.55, 0, 1, 0.45)` | leaving |
| `--motion-shift-sm` | 16 px | text, labels, small elements |
| `--motion-shift-lg` | 24 px | cards, sections, media |
| `--motion-stagger` | 60 ms | between siblings |
| `--motion-stagger-fast` | 50 ms | between hero words |

Rules: transform and opacity only (no width/height/margin/font-weight animation), `will-change` only on the hero pattern layer and the glow, IntersectionObserver instead of scroll listeners, CLS 0, direction follows the writing direction (`[dir='rtl']` overrides, logical properties, the `translate` property for arrows so the RTL `rotate` is untouched), light and dark alike. Component scripts are ES modules that run once per full load, so each registers an idempotent `init` through `onPageLoad` (`astro:page-load`) and marks bound elements with a data attribute; timers/observers are cleared on `astro:before-swap`. View transitions: `ClientRouter` on every site page except `/discover-taif/`, `/partners/*` and `/menu/`. The internal review page `/_motion/` was removed on 22 Oct 2026; review motion on the real pages. Partners pill (23 Oct 2026): bronze hairline pill in the utility row; on the first page view of the session the hairline draws around it once from the reading-start edge over `--motion-slow` (the hero rule's token) after a slow + base delay — SVG stroke-dashoffset, "seen" in sessionStorage; hover/focus brightens the border and lifts it 1 px over `--motion-fast`; reduced motion → static border. QA: `node scripts/motion-check.mjs`, `node scripts/drawer-check.mjs`, `node scripts/datepicker-check.mjs`, Lighthouse via `node scripts/lh.mjs <label>` (medians of repeated runs — the lab machine is noisy), clips via `node scripts/motion-clips.mjs <scenario>`.

## 8. Booking-request flow (phase 1)

Form fields (rebuilt 23 Oct 2026, Ahmed): branch first; room type filtered by the branch (optional, «أي غرفة متاحة»); check-in / check-out from the calendar range picker — no typing anywhere (Ahmed, 23 Oct 2026): `DateRangeField.astro` + `src/lib/daterange.ts`, the one component for every date field incl. the partners form; ISO values in hidden inputs; no past dates in Asia/Riyadh, departure after arrival, up to 31 Dec of next year, night count with Arabic plural; adults (min 1) and children (min 0) as steppers; extra beds (rooms.json → `extra_beds_max`, 0–2 per room type; the field is hidden when the room takes none; with «أي غرفة متاحة» up to the branch's highest `extra_beds_max`). The extra bed is a suggestion, never a requirement (rule change, Ahmed 23 Oct 2026): party size never blocks a request (technical bounds only); still enforced client and server: extra beds ≤ the room's `extra_beds_max` (or the branch maximum with «أي غرفة متاحة»). When adults exceed the capacity the form suggests the missing beds (within the maximum, editable down to 0) with a non-blocking note; fewer beds than needed, or a room that takes none, shows a non-blocking note that the reception will coordinate; the row stores `needs_coordination` (adults > capacity + extra beds) and the reception notification flags it; children have no business limit. The reception notification flags «أسرّة إضافية: N — تحتاج تأكيد التوفر» with the estimated total (fee × nights × beds); the fee is snapshotted on the stored request (`extra_bed_fee_per_night`); breakfast — a required choice with no default (`with` | `without`, stored as the `breakfast_choice` enum; no price shown); full name (Arabic or Latin letters, spaces, hyphen, apostrophe, ≥ 3 characters, no digits); phone/WhatsApp **required** with a searchable country-code selector (self-hosted flag images from `scripts/flags.mjs`, never emoji or a CDN; default Saudi Arabia), validated per country with libphonenumber-js and stored as E.164 — since 28 Oct 2026 the ONE shared field `src/components/PhoneField.astro` (variants `booking` / `partners`) over `src/lib/country-select.ts`, `src/lib/phone.ts` and `src/lib/countries.ts`, used by the booking form and the partners enquiry wizard alike (the wizard's look comes from `src/styles/partners-phone.css`, scoped under `.legacy-partners`): search by the name in the page language, the English name, the ISO code and the dial code (with or without +, Arabic-Indic digits converted), ranked exact ISO → dial code → name start → name contains; a pasted international number (+ / 00) switches the selector and keeps the national part; the partners draft keeps `phone_country`, «مسح البيانات» resets it to Saudi Arabia, an older draft takes the country from a stored international number; the wizard's business «country» field stays independent; email **optional**, validated when given; notes. Every rule lives once in `supabase/functions/booking-request/rules.ts`, imported by the form and by the Edge Function (the server never trusts the client). Arabic labels; no raw field names ever visible; inline errors on blur and submit with aria-describedby / aria-invalid, focus to the first invalid field; one summary line above the buttons; submit disabled with a spinner while sending; on failure a clear message plus the WhatsApp hand-off prefilled with every field.

Children's ages (Q2, 24 Oct 2026): one select per child (0–17), asked only when children > 0 **and** breakfast = «مع الإفطار»; they price breakfast and nothing else, so an older client without them is still valid (the booking becomes a request with reason `needs_ages`).

**Instant confirmation (phase 2a, DECISIONS.md 2026-10-25):** once a room type and both dates are set the form shows the runtime quote (§5) with a badge — «تأكيد فوري» or «طلب حجز — يؤكده الاستقبال» plus the reason — and the submit label follows («أكّد الحجز» / «أرسل الطلب»). A booking is confirmed instantly only when a specific room type is chosen, the branch's `instant_booking` and `show_prices` switches are on, every night has a rate, is open (not stop-sold) and has `rooms_to_sell ≥ 1`, `needs_coordination` is false, no extra bed is requested (Q4), a same-day arrival is submitted before 20:00 Riyadh and the stay is ≤ 30 nights (Q5, editable in Settings); everything else is a request as before. ## 9c. Dashboard interaction rules (Ahmed, 28 Oct 2026 — DECISIONS.md 2026-10-28)

- **Dialogs never close by accident.** Every modal, drawer, sheet and confirm is the shared `Modal` / `Drawer` of `admin/src/components/ui.tsx` with the one dirty guard `admin/src/lib/dirty.ts` — no per-dialog or per-page patches. An outside press (click, tap, pointer-down, a press that starts inside and ends outside such as a text-selection or scrollbar drag) does nothing: no close, no flicker, no focus loss; no swipe-to-dismiss. A dialog closes only through its × or its «إلغاء» («إغلاق» for read-only ones, `CancelButton`), or after a successful save; Esc behaves exactly like ×. Dirty = any control inside differs from its value at open (text after `west()` + trim, numbers as numbers — «٥٠» = «50»; checks / radios / `aria-pressed` chips / segments; a control added or removed after the scope settled; typing then restoring = clean): × / «إلغاء» / Esc open «تعديلات غير محفوظة» — «لديك تعديلات لم تُحفظ في هذه النافذة. هل تريد الإغلاق وتجاهلها؟» — «متابعة التعديل» (default focus; Esc) / «تجاهل التعديلات والإغلاق» (destructive); the confirm itself ignores outside clicks.
